# Code review — 2026-09-08

Four reviewers, one each on the runtime package, the builders, the contract tables, and
process lifecycle/IPC. About fifty findings between them; this is the deduplicated set
with my own judgement on each, ordered by what I would fix first.

I have marked every finding **VERIFIED** (reproduced, or demonstrated by running code),
**CONFIRMED** (read the lines and agree), or **UNSETTLED** (plausible, needs a check I
could not run). Two findings I disagree with are at the bottom with reasons.

## 1. A live file is shrunk under a mapped reader — SIGBUS, not an exception

`appletd/maskbuf.py:239-241` — **VERIFIED**, the reviewer reproduced it: map 1 MB,
`ftruncate` to 4 KB on a second fd, touch offset 512 KB, process dies with exit 138
(128 + SIGBUS).

`MaskWriter` opens with `O_CREAT` and no unlink, so an existing buffer keeps its inode
and `ftruncate` can make it **smaller** while a reader is mapped to the old length.

Two reachable paths, and they point in opposite directions:

* **TouchDesigner kills the sidecar.** TOP Input at 1280×720, user drops the feeding
  TOP to 640×360 → `td_add_topinput.py` builds a new `MaskWriter` on the same path →
  file shrinks → the sidecar's pump thread is mid-`read()` and dies on signal 10, with
  **nothing in the log**, while the panel still says Running.
* **The sidecar kills TouchDesigner.** `Segquality` accurate → fast shrinks the mask
  buffer from ~3 MB to ~48 KB while `seg_mask`'s Script TOP reads it at 60 Hz on the
  main thread. The whole application dies with no traceback.

The `os.stat` at `maskbuf.py:430` narrows the window and cannot close it — one stat per
read, taken before the header parse and the payload copy.

**Fix:** never mutate an inode a reader may hold. Grow-only, or write to a temp path in
the same directory and `os.rename`. The reader already handles a new inode correctly —
its own comment at `:426-428` describes rename as the safe pattern, and the writer
simply does not use it.

This is the one finding I would fix before anything else, because it can take down the
host application and leaves no diagnostic.

## 2. Two channels I added today are silently deleted from the output

`tools/td_add_screenspace.py:344,376` — **VERIFIED** by expansion:
`[screenspace] deleted with NO companion: ['hands_angle_x', 'hands_angle_y']`

I narrowed `_MERGED_CANDIDATES` in `spaces.py` this morning after `hands_angle_x` got a
meaningless `_tx` companion. The same `hands_*_x` wildcard is in `STREAM_TERMS` and
`_HANDS`, which is the pattern that **deletes** raw channels once they have a composed
twin. `hands_angle_x` has no twin, so it is deleted and nothing replaces it.

`Screenspaceonly` and `Twohands` both ship ON, so this is the default configuration.
The build writes a verified literal scope, but `screenspace_callbacks` **overwrites
`delscope` from `STREAM_TERMS` with no verification** on any change to
`Screenspaceonly`, `Stream*`, `Coordstx` or `Coordspx`. So the channels are present
after a rebuild and vanish the first time a stream toggle moves. `hands_angle_z`
survives, which makes it look like a partial channel set rather than a bug.

**Fix:** `hands_center_x`/`_y` by name in both places, matching `spaces.py`. Better: the
callback should reuse the verified string the build produced rather than rebuilding an
unverified one.

## 3. `Cameraflip` never reports "Requires Restart"

`tools/td_build_vision.py:1008-1016` — **CONFIRMED**, the list starts `["Camera",
"Inputmode", "Framesbuffer", …]` and `Cameraflip` is absent.

`start()` reads it and appends `--flip`, so it IS a launch flag; `launch_signature`
does not hash it, so `set_state` keeps saying **Running** and `Auto Refresh` never
restarts. Meanwhile `video_flip.flipx` applies instantly.

Consequence: the picture mirrors, Vision does not. Every landmark, the mask, depth and
flow are mirrored the wrong way relative to `outvideo`, the overlay sits on the wrong
hand, and `h?_chirality` reports the un-mirrored world. Nothing errors.

**Fix:** add `"Cameraflip"` to `launch_pars`. It is already in the watched list, so
only the signature is blind.

**Note:** this partly undoes today's decision to make `Cameraflip` restart itself. Both
should hold — the self-restart for convenience, the signature so the state is honest if
the restart is declined.

## 4. `apply_freeze` fires after its own countdown declared it cancelled

`tools/td_build_vision.py:446-451` — **CONFIRMED**. Mine, from today.

`tick_countdown` treats `Active` going off as "this can no longer happen" and restores
the state. `apply_freeze` has only the token check. So: `Freezetimer` 5, press `Freeze`,
switch `Active` off at second 2 → the countdown says "Stopped" and stops → three seconds
later `apply_freeze` still matches its token and **locks all five outputs**. The panel
says Stopped and the only documented unlock is turning `Active` back on.

`apply_refresh` gets this right and its comment says why. The two scheduled actions
disagree about the same precondition.

**Fix:** give `apply_freeze` the same `Active` guard.

## 5. Two sidecars can write one seqlock buffer, undetectably

`tools/td_build_vision.py:896-904` then `:616` — **CONFIRMED** by reading; the
interleaving is argued rather than reproduced.

`stop()` gives up 1 s after SIGTERM and only *prints*; `start()` then `Popen`s
regardless. The old sidecar can outlive that second because its signal handler only
sets a flag, and `run()` blocks in `start()` for the camera's ~1.5 s warm-up. Two
presses of `Restart` inside 1.5 s does it; so does a `Cameraflip` during warm-up, since
that calls `restart()` directly.

Both processes then write the same buffer with independent `seq` counters, and the
reader's four checks all pass because they are all against the new writer's counter. A
torn image is published as coherent. On the depth buffer the `aux` carries the affine
fit, so a fit from one process can be paired with pixels from the other — the exact
failure `_write_depth` exists to prevent.

**Fix:** escalate to SIGKILL after the deadline and re-poll; have `start()` refuse while
`running_pids()` is non-empty.

## 6. The panel reports "Running" for a sidecar this component did not start

`tools/td_build_vision.py:1093-1102` — **CONFIRMED**.

`running_pids()` is machine-wide by design, but `set_state` pairs it with a signature
stored in this COMP, which persists into the `.toe`. So a sidecar left running in a
terminal, plus a matching saved signature, reads as Running — and `ensure_running`
declines to start anything. The `sc_*` channels even arrive on the same port, so uptime
rises and the panel looks healthy while every launch flag describes a process that does
not exist. Two TouchDesigner instances holding the component do the same thing.

**Fix:** `Capturepid` is already written — require it to be in `running_pids()` for
"Running", with a distinct third state when some other sidecar is up. Keep `stop()`
machine-wide, which is the deliberate part.

## 8. Wrong or misleading where it matters

* **`MaskImage.coverage` is always 0.0 for an instance mask**
  (`segmentation.py:82-91`) — **CONFIRMED**. It thresholds at `>= 128`; instance masks
  carry 1..4. The one signal for "is this mask empty" always says empty on that path,
  and it is O(pixels) in pure Python — 3 M iterations at `accurate`.
* **One unreadable observation discards the whole frame**, and the comment says it does
  not (`pose.py:202-211`, `engine.py:340-347`) — **CONFIRMED**. Three people in shot,
  one bad observation, and the two good skeletons never reach the box.
* **`streams_started` returns what was REQUESTED**, contradicting its own docstring
  (`source.py:638-646`) — **CONFIRMED**. `sc_segment` can read 1.0 with nothing
  producing a mask. Not currently reachable through the sidecar CLI, which keeps the two
  in step — one argument away.
* **`_reset_session_state` resets 3 of 12 counters** (`engine.py:1207-1224`) —
  **CONFIRMED**. Post-restart drop rates are the sum of two sessions.
* **The Over TOP comments name the wrong input** in both builders
  (`td_add_video.py:148`, `td_add_overlay.py:283`) — **CONFIRMED**. The wiring is right;
  `td_add_video.py`'s comment says the overlay connects to input 1, which is where the
  camera is. Anyone trusting it drops the camera from the composite.
* **`_flow_writer` is never closed** (`sidecar.py:424`) — **CONFIRMED**, found
  independently by two reviewers. 7.2 MB mapping released only by process exit, and no
  counterpart to the `_mask_writer`-is-None guard.
* **The generated `_apply_gating` lost the empty-keep-list guard**
  (`td_add_groups.py:966-973`) — **CONFIRMED**. The file's own docstring flags this
  function as the hand-copied, drift-prone half. Currently masked by a corrective pass a
  frame later.
* **`_refusal` measures the spread over ALL pins after one was dropped**
  (`pins.py:249-251`) — **CONFIRMED**. Sends the user looking for a pin behind the
  camera when two survivors are too close together.

`_check_stream_patterns`, `_check_face_slots`, `_check_keypoint_names`,
`_check_keypoints` — are called only from `main()`, i.e. only inside TouchDesigner at

`clap_count`, `apart_count`). `_check_stream_patterns` passes because it builds its
universe from `derived_roles`, which classifies 24 of ~223 channels.

## Two findings I disagree with

* **"The header memcpy is not ordered against the `seq` field."** The reviewer says so
  itself: for a stale even `seq` to be *accepted*, the writer's 4-byte store would have
  to stay invisible for the entire payload copy. Worth the one-line tightening, not
  worth calling a defect.
* **`pins.sample()` wrapping on a frame narrower than 7 px.** The depth map is the
  model's fixed 518×392 output. Unreachable outside tests. Add the guard if the file is
  open anyway.

## What the reviewers checked and found sound

Worth recording, because it is where the design earns its keep:

* **The seqlock's aux/pixel pairing is correct.** `_aux` is stamped during the odd
  phase, so a reader accepting an even `seq` always has the aux belonging to those
  pixels — a depth fit cannot be paired with a neighbouring frame's map.
* **The camera path's teardown order is right**, including unregistering the delegate
  before the `dispatch_sync` barrier.
* **Every pyobjc out-param selector is annotated and correct.**
* **All 27 generated templates render, escape `%` correctly, and use no undefined
  name.** `_trim_source()` reads the TRIM SCOPE block off disk, so that duplication
  genuinely cannot drift.
* **`EMBEDDED_MODULES` covers the full import closure**, including every
  `from appletd.…` in every generated DAT.
* **Every parameter any builder creates is in `td_pages.LAYOUT`**, and every parameter
  in `LAYOUT` is still created.
* **The lazy frames-buffer open is complete**, and the ABA on a writer restart is
  handled correctly by `frames.py`'s gap arithmetic.

## Recommendations, in order

1. **Fix the SIGBUS (1).** It can kill TouchDesigner and leaves no diagnostic.
2. **Fix the six findings that are mine from today** (2, 3, 4, 7's `human?_conf`, 10,
   and the producer already fixed). They are in shipped code on `main`.
3. **Enumerate the lists that must agree, in one place, and test it.** This is the
   structural fix and the reason this review found what it did. A single module —
   `appletd/contracts.py`, importable without pyobjc — that names every parallel list
   and asserts they agree, called by one test. Then "did I update all of them?" has an
   answer that is not "read four files".
4. **Run the five build-time guards in the suite.** Twenty lines, no TouchDesigner.
5. Then the lifecycle findings (5, 6) and the label-lies (7).
6. The stale comments last, in whatever edit next touches those lines.

Nothing here needs a decision from Omer except the ordering.
